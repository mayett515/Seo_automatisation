## Customer Report Aggregate Foundation

- Implemented ADR 0021 slice 1 without widening Page, Release, worker, AI, or frontend modules.
- Replaced the empty skeletal `reports` table through migration `0037_customer_report_aggregate` with the stable monthly report issue, bounded generation run, versioned report candidate, normalized claim/evidence/link projection, and append-only lifecycle event tables.
- Added database ownership for one canonical issue identity, one active generation per issue, one open draft/ready candidate, one current published head, sequential versions, correction lineage, project-coherent pointers, exact row-version increments, draft-only semantic mutation, reviewed freeze, and append-only lifecycle evidence.
- Kept publication fail-closed: the aggregate migration rejects `published` and `superseded` writes until reviewed HTML artifacts and the digest-bound human publication/correction transaction ship together.
- Added `ReportsService` as an internal application service with no controller. Generation admission locks the stable issue, records an idempotent actor-backed run, and pins the expected issue/candidate version and digest.
- Added snapshot admission that parses the strict contract, composes deterministic eligibility for every claim, recomputes the canonical fact-projection SHA-256, canonicalizes and hashes the complete snapshot, verifies source rows and typed verification/deployment/rollback relationships belong to the report project, and transactionally persists canonical truth plus normalized provenance.
- Bound generation idempotency replays to the original issue, actor, evidence cutoff, and narrative mode so a reused key cannot silently adopt changed request semantics.
- Folded the external review hardening into the unreleased migration: proof tiers are DB-bounded, generation base/result references are issue-coherent, review promotion compares exact canonical and normalized projection sets, lifecycle events prove exact transitions, conditional writes verify their affected row, and decision notes reject unsupported controls.
- Resolved draft regeneration according to ADR 0021: semantics may change only while `draft` under expected issue/report versions; `ready_for_review` freezes the digest; request-changes is the persisted human transition that reopens regeneration. Review and generation completion both lock issue before report so their race has one legal winner.
- Added `fast-check@4.9.0` as a domain test dependency and property-tested canonical identity across generated permutations of claims, evidence, actions, narrative slots, and nested reference keys.
- Added a DB-backed integration suite covering first-generation empty-set contention, canonical/provenance persistence, review freeze, request-changes/regeneration, duplicate completion, review-versus-regeneration, and cross-project source substitution.

## Release Transition Ownership Hardening

- Closed the release-plan stale-writer findings before the report assembler begins consuming release evidence.
- Made preflight and deploy approval serialize on the release-plan row, re-read current status inside the transaction, and update only from explicit expected-status sets.
- Made preflight checks and readiness one transaction. A rerun from `approved_for_deploy` now restores included `release_candidate` page versions to `approved` in that transaction, while terminal plans reject before check or rollback-point preparation.
- Made the API's post-enqueue deploy projection and the worker's deployment-ledger start compare-and-set `approved_for_deploy`/`deploying`; a concurrent terminal transition now leaves only a fail-closed queued job and cannot be revived into provider work.
- Kept verification and rollback on the same rollback-point-before-deployment-before-plan ownership order. Verification now locks rollback execution evidence and compare-and-sets the deployment before coarse plan/page-version projection; a late healthy result may finish its detailed verification audit but cannot project during an active restore, manual reconciliation, or committed rollback truth.
- Centralized active rollback evidence recognition in the pure domain vocabulary used by rollback and verification, and persisted projected/not-applicable/suppressed lifecycle outcomes with stable suppression reasons on terminal verification audit.
- Made rollback intent compare-and-set current failed-plan eligibility in the same transaction as `restore_in_flight` evidence, so a plan change after context loading stops before provider restore and rolls the intent back.
- Guarded verified deploy replay to `deploying`/`live` plans so an old successful deployment row cannot revive failed or rolled-back plan truth.
- Added a forced PostgreSQL plan-lock race proving a concurrent terminal transition defeats deploy approval without an approval row, plus worker interleavings proving active and committed rollback ownership defeats late healthy projection.
