## Reviewed Customer Report HTML Artifacts

- Implemented ADR 0021 Slice 3 as an authenticated review and deterministic artifact path. Submit-for-review now requires the exact snapshot digest and row version, persists the human lifecycle event, creates a pending HTML artifact, and freezes the report in one issue -> report -> artifact transaction.
- Added migration `0040_customer-report-html-artifacts` with a separate report-artifact lifecycle, partial active/staged identity uniqueness, exact snapshot/manifest binding, immutable artifact identity and terminal evidence, deferred review binding, delete protection, and a database rule that review cannot exist without an exact active artifact.
- Request-changes takes the same locks, expires pending/running/staged artifacts before returning the report to draft, and therefore wins safely against a renderer that wrote bytes but has not yet attached them.
- Added a purpose-named immutable private artifact storage port on the existing filesystem and S3 adapters. Filesystem uses create-if-absent writes; S3 uses `IfNoneMatch: "*"`; exact-byte retries are idempotent and different-byte reuse fails closed.
- Added the `customer_report_html_render` worker. It re-parses and re-digests the stored canonical snapshot and strict render manifest, renders bounded script-free HTML without live-source, AI, or provider reads, verifies immutable storage evidence, and stages bytes only while the exact reviewed report still owns the artifact.
- Added a separate bounded `artifact_capture` recovery lane with `jobId = artifactId`. Missing transport reuses the same identity; exhaustion and completed transport without staged truth become visible failed artifact evidence without changing report publication state.
- Closed the pre-publication review findings by formatting proof dates through the manifest's `Europe/Berlin` timezone, routing every claim body through typed escaped inline fragments, renaming migration 0040 descriptively, checking exact filesystem metadata replay, mapping post-review queue exceptions to 503, and pinning staged-artifact expiration in PostgreSQL coverage.
- Added contract/domain/adapter/renderer tests and DB-backed artifact staging, replay, request-changes race, storage-evidence failure, same-id recovery, and recovery-exhaustion cases. Local package unit suites pass; the DB-backed cases remain gated by GitHub Actions because `TEST_DATABASE_URL` is not configured locally.

## Release Transition Ownership Hardening

- Closed the release-plan stale-writer findings before the report assembler begins consuming release evidence.
- Made preflight and deploy approval serialize on the release-plan row, re-read current status inside the transaction, and update only from explicit expected-status sets.
- Made preflight checks and readiness one transaction. A rerun from `approved_for_deploy` now restores included `release_candidate` page versions to `approved` in that transaction, while terminal plans reject before check or rollback-point preparation.
- Made the API's post-enqueue deploy projection and the worker's deployment-ledger start compare-and-set `approved_for_deploy`/`deploying`; a concurrent terminal transition now leaves only a fail-closed queued job and cannot be revived into provider work.
- Kept verification and rollback on the same rollback-point-before-deployment-before-plan ownership order. Verification now locks rollback execution evidence and compare-and-sets the deployment before coarse plan/page-version projection; a late healthy result may finish its detailed verification audit but cannot project during an active restore, manual reconciliation, or committed rollback truth.
- Centralized active rollback evidence recognition in the pure domain vocabulary used by rollback and verification, and persisted projected/not-applicable/suppressed lifecycle outcomes with stable suppression reasons on terminal verification audit.
- Made rollback intent compare-and-set current failed-plan eligibility in the same transaction as `restore_in_flight` evidence, so a plan change after context loading stops before provider restore and rolls the intent back.
- Guarded verified deploy replay to `deploying`/`live` plans so an old successful deployment row cannot revive failed or rolled-back plan truth.
- Added a forced PostgreSQL plan-lock race proving a concurrent terminal transition defeats deploy approval without an approval row, plus worker interleavings proving active and committed rollback ownership defeats late healthy projection.
