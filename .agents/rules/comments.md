# Comments

A comment explains why; the code already explains what.

- Comment the non-obvious constraint: the reason for an ordering, a magic
  threshold, a workaround for an upstream bug. Link the issue when the reason
  lives outside the repo.
- Never restate the code in prose, narrate obvious syntax, or leave a comment
  describing behavior the code no longer has.
- Never use a comment to apologize for a structure you could fix, or to prop
  up weak naming — rename instead.
- No TODO without an owner or issue reference.
